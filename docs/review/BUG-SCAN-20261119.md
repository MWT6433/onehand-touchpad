# OneHand 触控板缺陷扫描（2026-11-19）

## 0. 结论摘要

通读 23 个 Java 文件，P0 四节共 25 条发现，分别为 8、7、5、5 条。以下路径有直接用户后果。

- **手柄看不见或失灵。** `0.1×` 下普通模式手柄可以完全画出自身窗口。手柄触摸层添加失败时仍会被视为已挂载，停靠面板随后被禁止接收触摸。见 X1、C1。
- **触摸取消或任务关闭作用在错误的对象上。** 回声过滤可能跳过已接收手势的取消收尾。任务抽屉缩小时，关闭热区重叠，点下一行可关闭上一行。见 C3、T1。
- **状态与实际结果分叉。** 服务已开启但窗口不运行时，设置按钮显示「启用」却发出停用请求。Shizuku 任务查询失败被当作已成功查空，RPC 清掉 API 后也可能维持不可重连的绑定状态。见 A1、ZI1、ZI2、ZS1。

### 8.3 与任务书的差异

- 基线实测为干净且第 45 个提交，23 个 Java 文件和 `12689 total` 与任务书一致。处理顺序中漏列了 `ShizukuSettingsService.java`，在 `PadTileService.java` 后补读并单独落盘。`PadController` 的截断试读如 §8.1 所列。
